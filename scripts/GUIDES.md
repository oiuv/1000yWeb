# 游戏资料维护

游戏资料完整保留参考文档的正文、表格、原文链接和数值；不按是否开放筛选，不与本服调整混写。游戏特色与自行调整另行说明。

资料为已生成的静态 HTML，随代码一起发布。部署仍然只需更新代码，不需要额外构建或连接资料仓库。

## 同步资料

本地安装开发依赖后执行：

    node scripts/import-guides.mjs "<游戏资料目录>" "<item.png>" "<Item.sdb>"

- 资料目录只读取 Markdown 正文；README 用分类入口代替。原始资料和游戏资源不会被改写。
- 生成目录页、文章页、全文索引，以及用于核对来源的文件清单。
- 引用其他已导入资料时链接到本站；范围外的文档链接保留到公开资料仓库。
- 将完整物品图集复制到网站静态资源。图集为 8 列，每格 120×120；按物品表的 Shape 编号取图，编号从 0 开始。导入器只提取名称与图号，不发布原始物品表。
- 图标优先按显示名称 ViewName 匹配 Shape，内部名称 Name 作为补充；同一显示名称对应多条记录时采用表中首个有效图号，作为该名称的资料示意图。名称两端空白会忽略，不做模糊匹配；没有匹配的资料正常显示文字。
- 本次使用的图集是黑底 RGB 图片，不作抠图或改色处理。
- 输出页面文件名由资料相对路径确定；重命名或删除来源文件后，核对并移除不再引用的旧文章页。

原始 Markdown 的二、三级标题会进入网页目录。装备名称使用标题，属性、取得方式和品系使用该装备下的列表；续行数值不能另设标题。发现排版错误时先修正资料原文，再同步网页，保留原有文字与数值。

导入前会校验全部 Markdown（含索引）的编码、换行、一级标题、标题层级、列表符号与表格列数；有错误时报告文件名和行号，不写出新页面。该检查不判断游戏数值是否正确，也不代替人工检查章节归属、表头含义和浏览器排版。

同步后运行 npm test，检查 Git 差异，再在本地预览中确认分类、搜索、表格和图标。只提交本次相关的静态资料和资源。
